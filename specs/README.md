# API Specifications

OpenAPI 3.0 YAML files describing each backend service boundary. These specs are
the single source of truth for API clients generated by Orval into
`src/shared/api/generated/`.

## Conventions

- One file per backend service boundary, named `<service>.openapi.yaml`.
- YAML is excluded from ESLint, tsconfig, and the bundler (it never ships in the
  build output).

## Files

| File | Service | Owner |
|---|---|---|
| `users.openapi.yaml` | Users (current session) | frontend |
| `tables.openapi.yaml` | Tables (demo CRUD) | frontend |

## Update process

1. Edit the relevant `<service>.openapi.yaml` when the backend contract changes.
2. Regenerate clients:

   ```bash
   pnpm codegen:api
   ```

3. Never hand-edit `src/shared/api/generated/` — it is overwritten on regeneration.
